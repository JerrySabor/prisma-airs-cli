# Spec: TS `airs-cli` AI Gateway (`aigateway`, renamed `gateway`, M6e)

Commands covered: every node under `aigateway` (`src/cli/commands/aigateway.ts` and `src/cli/commands/aigateway/*`): `workspaces|workspace`, `scopes`, `telemetry` (cost, every metric read, `group-by`, `logs`, `cache`, `feedback`, `filter-boundaries`), the inventory groups (`api-keys`, `audit-logs`, `configs`, `deployments`, `guardrails`, `integrations`, `mcp integrations`, `organisations`, `plugins`, `providers`), `admin-guardrails`, `inference`, and `report|dashboard` (command surface, checks and request sequence; its HTML/Markdown renderer is shared with the other environment reports and is not re-specified here). In airs-cli-rs the group is `gateway` (MILESTONES "Renames"); every TS name below keeps its TS spelling.

- How behaviour was captured: the reference build (`dist/cli/index.js`, node v24.21.0) ran against a stateful loopback stub (`node:http` on `127.0.0.1`, random port; scratchpad `tsgwspec/stub.mjs`). It implements `POST /oauth/token`; the data plane `/ai_gw/v2` (workspaces, configs, guardrails, providers, `api-keys/{service,user}`, `logs/charts/<metric>`, `logs/groups/<dim>`, `logs`, `analytics/filter-boundaries`); the admin plane `/ai_gw/admin/v2` (workspaces with create/PUT/DELETE kept in state, admin guardrails and MCP mappings, integrations, `utils/static-resources/{ai-providers,schema}`, MCP integrations, deployments, plugins, organisations, audit logs); IAM `/iam/v1/scopes` (create/get/PUT/DELETE kept in state); and the inference runtime `/inf/v1` (`chat/completions`, `responses`, `embeddings`, SSE when `stream: true`). Every other response body is generated from the SDK's own zod response schema (`tsgwspec/gen.mjs`), so it always validates. The stub logs method, path, raw query, auth scheme, `x-tsg-id`, content type, the presence of `x-portkey-api-key`, and the raw body, and accepts a fault plan (status, raw body, headers such as `Retry-After: 0` or `x-opa-decision: false`, a hang, a repeat count).

Fixture ids are `11111111-1111-4111-8111-<12 digits>` (written `U(n)`); workspaces `U(1)` `ws-main-a-349e0e` "Main A" (active, default, data-visible), `U(2)` `ws-produc-985697` "Production" (active, admin only), `U(3)` `ws-old-aaaaaa` "Old" (archived); scopes `main_airs_workspace_1852583913`, `ws_production_bx7qw0`, `ws_orphan_zzzzzz` (unbound). Fake sensitive values are `PRIVATE-…`.
  - **Endpoints and credentials.** `aiGatewayClientOptions` (`co.ts:79-86`) passes `clientId`, `clientSecret`, `tsgId` from `mgmt*`, `tokenEndpoint: mgmtTokenEndpoint ?? DEFAULT_TOKEN_ENDPOINT`, `dataEndpoint: aiGwDataEndpoint ?? DEFAULT_AI_GW_DATA_ENDPOINT` (`https://api.apps.paloaltonetworks.com/ai_gw/v2`), `adminEndpoint: aiGwAdminEndpoint ?? …/ai_gw/admin/v2`, `iamEndpoint: iamEndpoint ?? …/iam/v1` (`SDK:125-130`). The SDK's environment fallbacks `PANW_AI_GW_DATA_ENDPOINT`, `PANW_AI_GW_ADMIN_ENDPOINT`, `PANW_IAM_ENDPOINT` and the `PANW_AI_GW_*`/`PANW_MGMT_*` credentials (`SDK:22709-22720`) are therefore never reached for the management planes. **Inference is different**: `inf.ts:152-157` passes `endpoint: config.aiGwInferenceEndpoint` and `apiKey: config.aiGwInferenceApiKey` unguarded, so when the tenant lacks them the SDK reads `PANW_AI_GW_INFERENCE_ENDPOINT` / `PANW_AI_GW_INFERENCE_API_KEY` (`SDK:22444-22445`; captured, §8.2). `aiGwTokenEndpoint` is a retired key (`schema.ts:66-71`). Other environment variables that change gateway behaviour: `PANW_AI_SEC_TIMEOUT_MS` (per-attempt timeout of management requests, `SDK:10095`), `PANW_AI_SEC_DEBUG`, `PANW_AI_SEC_DEBUG_BODY` (§2.12), `TZ` (telemetry windows, §2.13), `AIRS_CLI_INVOKED_AS` (`airs cli` spelling in hints and examples), `FORCE_COLOR`/TTY for chalk.
  - Every node run preloaded a guard (`--import`) that replaces `globalThis.fetch` and `dns.lookup` and refuses any host other than `127.0.0.1`; its log stayed empty in every run.
  - Signals were sent with `kill -INT|-TERM` during a hung request; prompts ran on a pty.
- No real tenant or credential file was read; no host other than loopback was contacted.
- Captures are JSON strings (`"\n  ..."`), uncoloured (stdout a pipe) unless stated. The token request (`POST /oauth/token`, `grant_type=client_credentials&scope=tsg_id%3A100`) precedes the first management request of every run that reaches the network and is omitted from the request lists below unless it matters.

## 1. Command surface (help verified)

Registration (`gw.ts:128-512`): `aigateway` (`Manage and observe Prisma AIRS AI Gateway resources`, action = print own help) registers, in order, the inventory groups (`inv.ts:1147-1262`: `api-keys`, `audit-logs`, `configs`, `deployments`, `guardrails`, `integrations`, `mcp`, `organisations`, `plugins`, `providers`), `admin-guardrails` (`ag.ts:39-177`), `report|dashboard` (`rep.ts:18-124`), `inference` (`inf.ts:97-226`), `workspaces|workspace` (`gw.ts:139-355`), `scopes` (`gw.ts:357-470`) and `telemetry` (`gw.ts:472-511`, `tel.ts:144-252`). After registration (`program.ts:204-206`): every `list` gets alias `ls` and every non-hidden `delete` gets `rm` (`program.ts:42-51`; the hidden `workspaces delete` gets none, so `workspaces rm …` is an excess argument: `error: unknown option '--force'` with `--force`, exit 1, captured); every `list`/`get` without `--output` gets one (none lacks it); the `--offset/--all/--max` completion of `program.ts:54-70` never applies (no gateway `list` has `--limit`/`--offset`); help sorts options and subcommands. Every group node prints its help on stdout and exits 0 (`showHelpOnEmpty`, `sh.ts:45-47`); an unknown subcommand is `error: too many arguments for 'aigateway'. Expected 0 arguments but got 1.` (exit 1, captured, also for `workspaces bogus` and `scopes list extra`).

## 2. Shared behaviour

### 2.1 Clients, planes, headers

- Two construction paths, both lazy (help and completion never load credentials): `createService()` → `new SdkAiGatewayService(aiGatewayClientOptions(await loadConfig()))` (`gw.ts:34-37`) for `workspaces`, `scopes` and `telemetry cost`; `createAiGatewayClient()` → `new AIGatewayClient(…)` (`sh.ts:23-33`) for everything else except `inference` (its own runtime client, §8) and `report` (`numRetries: 0`, §9). Both call `assertManagementCredentials` (`co.ts:34-42`): `\n  ✗ Error: Management credentials are not configured (missing mgmtClientSecret). Run 'airs-cli tenant set test <key>' for mgmtClientSecret (secrets prompt hidden, or use --stdin)\n\n`, exit 1 (captured). One OAuth token per invocation, fetched on the first request.
- Planes (`SDK:22700-22720`): **data** (`aiGwDataEndpoint`) = telemetry, `workspaces list|get` (default plane), configs, workspace guardrails, providers, `api-keys`; **admin** (`aiGwAdminEndpoint`) = workspace create/update/delete and `--plane admin` reads, admin guardrails, `guardrails.getCatalog` (`/utils/static-resources/schema`), integrations and the provider catalog, MCP integrations, deployments, plugins, organisations, audit logs; **IAM** (`iamEndpoint`) = scopes.
- Headers on every management request: `Authorization: Bearer <token>`, `x-tsg-id: <mgmtTsgId>` (`TsgHeaderAuth`, `SDK:14662-14679`; also on IAM), `User-Agent: PAN-AIRS/0.34.0-typescript-sdk`, `service-name: api`, `Content-Type: application/json` on bodies. Base URLs lose trailing slashes (`SDK:10117`). Bodies are serialised after the request schema's `safeParse`, so **key order on the wire is the zod schema order**, not the input order (captured: `{"name":…,"description":…,"scopes":…,"alert_emails":…,"expires_at":…,"organisation_id":…,"workspace_id":…,"type":…}` for a service key built from flags in a different order).
- `numRetries` is not passed (except `report`), so the SDK maximum 5 applies (`SDK:30,11111-11114`).

### 2.5 Validation order (captured)

- Class W/WW: (preAction for `list`/`get`: tenant + format) → format (tenant) → banner if pretty → flag checks → `createService` (tenant again, credentials) → SDK checks → requests. `telemetry cost` parses `--days` and the chart filters **first** (exit 2 even with no tenant, captured) and only then resolves the format.
- Class WD: banner → confirmation (non-TTY refusal before the tenant is read) → `createService` → requests.
- Class L/D: preAction (tenant, format) → `resolveOutput` again → `createAiGatewayClient` (credentials) → the load callback (CLI parsing inside it, SDK checks) → request. The telemetry metrics of `registerMetric` (`tel.ts:70-93`), `logs list` and `audit-logs list` parse their window and paging flags **inside** the callback, so a bad `--days`, `--start` or `--current-page` is exit 2 but only after the tenant and credentials (captured: no tenant + `--days 0` → the no-tenant error, exit 1). The filtered metrics (`latency`, `requests`, `tokens`, `tel.ts:95-112`) and `group-by` (`tel.ts:200-211`) parse the window and filters **before** the tenant (exit 2 with no tenant, captured).
- Class G: format (tenant) → `buildStructuredRequest` (file read, flags, schema; exit 2 on failure) → client → SDK checks → request. `integrations create|update` use the one-argument `runWrite` overload (`inv.ts:614-647`): the client is built **before** validation, `--ai-provider <slug>` fetches the catalog (token + `GET …/utils/static-resources/ai-providers`) **before** the body is checked, and the credential-less refusal comes after that request (captured).
- Class C: format (tenant) → prepare (structured body, exit 2) → confirmation → client → request.
- Class S: prepare (structured body, exit 2, **before the tenant**) → the destination check (`Choose --secret-output <path> (recommended) or --show-secret before requesting a one-time credential`, exit 2, before the tenant, captured) → format (tenant) → reserve `--secret-output` (`open(path,'wx',0o600)`) → confirmation (rotate only) → client → request.
- Class I: format (tenant) → config with `--endpoint` → prompt/file/model checks → stream+yaml → request schema → `--timeout` → client (endpoint and key checks) → request (§8).
- Class R: all argument checks (exit 2) → output-path existence → tenant → requests (§9).

### 2.6 HTTP error text and retries (captured)

- No gateway request sets `safeErrorMessages`, so `executeWithRetry` (`SDK:9786-9850`) builds the message with `extractErrorMessage` (`SDK:9713-9725`): a problem-details body becomes `AISEC_CLIENT_SIDE_ERROR:API error 422; [withheld]`; otherwise the JSON `message` (or `error_message`, `data.message`, `error.message`, `msg`) is printed **verbatim**, control characters included (captured `✗ Error: AISEC_CLIENT_SIDE_ERROR:evil \x1b[31mRED\nline2`; inference `AISEC_SERVER_SIDE_ERROR:upstream PRIVATE-ECHO` from `{"error":{"message":…}}`); a non-JSON body is printed whole (`AISEC_CLIENT_SIDE_ERROR:API error 400: PRIVATE plain body`); an empty 5xx body gives `AISEC_SERVER_SIDE_ERROR:API error 500`. The body's `errorCode` (`AB01`, `AB03`, `AB08`) is **not** part of the message.
- Every method, writes included, is re-sent up to 5 more times on 500/502/503/504, transport errors and per-attempt timeouts (default 60 s, `PANW_AI_SEC_TIMEOUT_MS`), honouring `Retry-After`. Captured: `configs create` against two 503s sent **3 POSTs** and printed one config; `api-keys service create --show-secret` against two 502s sent **3 POSTs** (three keys may have been minted; only the last is shown); `scopes create` after one 504 sent 2 POSTs; `workspaces archive` against a permanent 500 sent **6 DELETEs** then `✗ Error: AISEC_SERVER_SIDE_ERROR:API error 500` / `HTTP 500`; the post-create re-read of `workspaces create` against a permanent 500 sent 6 GETs and then fell back silently (§3.3); a hung list with `PANW_AI_SEC_TIMEOUT_MS=200` sent 6 GETs then `✗ Error: AISEC_CLIENT_SIDE_ERROR:Request timed out` (no HTTP line). No outcome-unknown text exists anywhere.
- 401, and 403 without `x-opa-decision: false`, clear the token and replay once (`SDK:10865-10872`): captured `token, GET(401), token, GET(401)` → `✗ Error: AISEC_CLIENT_SIDE_ERROR:expired` / `HTTP 401`; a 403 (no OPA header) also produced `token, GET, token, GET`. A 403 with `x-opa-decision: false` is sent once.
- Inference uses `numRetries: 0` (one attempt, no auth replay: a 401 is sent once; captured) and `redirect: 'error'`.

### 2.7 The 403 grant hint

`aiGatewayGrantHint` (`svc.ts:87-100`) runs on every gateway failure with status 403 (all runners). It prints with `ui.warn` (**stdout**, not quiet-suppressed) before the error: `  ⚠ 403: the service account is missing a workspace-scope grant (data plane, /ai_gw/v2). SCM Access Management edits the existing role row by default — use "Add Role" so the account ends up with both role rows, not one row moved.\n` when the error **message** contains `AB03`, otherwise `  ⚠ 403: the service account is missing a tenant-root admin grant (admin plane, /ai_gw/admin/v2). SCM Access Management edits …`. Because the SDK message never carries the body's `errorCode` (§2.6), a data-plane 403 `{"message":"Forbidden","errorCode":"AB03"}` gets the **admin-grant** hint (captured); only a message text containing `AB03` selects the data-plane hint (captured). IAM 403s also get the admin hint.

### 2.8 Structured request input (`--file`, named flags, `--set`, `--set-string`)

Used by every class G/C/S command (`si.ts:189-247`). Options added by `addStructuredInputOptions` (`si.ts:38-51`): `--file <path>` (`Advanced JSON/YAML request base; named flags override it`), `--set <path=value>` (`Set a typed JSON value at a request path (repeatable)`), `--set-string <path=value>` (`Set a literal string at a request path (repeatable)`).

- Precedence: file < named flags < `--set`/`--set-string`. The file is read with `readFile(path,'utf8')` (no regular-file check, no size limit; a FIFO or `/dev/stdin` is read), parsed as YAML when the path ends `.yaml`/`.yml` (js-yaml `load`), else JSON. Errors: `Unable to parse --file 'missing.json' as JSON or YAML: ENOENT: no such file or directory, open 'missing.json'`, `--file 'arr.json' must contain an object`, and the parser's message, which for YAML **quotes the file's lines** (captured: `Unable to parse --file 'bad.yaml' as JSON or YAML: bad indentation of a mapping entry (3:6)\n\n 1 \| name: x\n 2 \| secret: PRIVATE-YAML-SECRET\n 3 \|   bad: [indent\n----------^`) and for JSON gives a position (`Expected double-quoted property name in JSON at position 40 (line 1 column 41)`). All exit 2. Relative paths resolve against the cwd.
- Named flags map to request paths (`NamedRequestField`, dotted paths allowed); a flag with a parser reports `Invalid --<flag>: <reason>` where the flag name is rebuilt from the option key (`si.ts:169-171`), so the derived `customHeaders` field of `--header` reports `Invalid --custom-headers: Duplicate key: a` (captured).
- `--set path=value` parses `value` as JSON and falls back to the literal string; `--set-string` keeps the string (`si.ts:144-155`). `Expected path=value` when `=` is missing or first (`Invalid --set 'noequals': Expected path=value`). Dotted paths (`SDK:22819-22955`): `.`-separated properties, `[n]` indices, `\` escapes for `.[]\`; errors `Dotted path must not be empty`, `Invalid empty segment in dotted path: <path>`, `Unsafe dotted path segment: __proto__` (also `constructor`, `prototype`), `Duplicate dotted path` (two assignments to one path), `Dotted path shape conflict`, `Array index conflicts with an object path`, `Sparse arrays are not supported`; they surface as `Invalid AI Gateway request: AISEC_USER_REQUEST_PAYLOAD_ERROR:<msg>` (exit 2). Assignments may overwrite file or flag values (`replaceExisting`), not each other.
- Scalar parsers (`si.ts:53-142`): booleans `true|false` only (`Expected true or false`); integers `^-?(0|[1-9]\d*)$` and safe (`Expected an integer`, `Expected a safe integer`); dates `new Date(String(v))` (`Expected an ISO-8601 timestamp`); CSV trims and drops empty items (`Expected a non-empty comma-separated list`); JSON (`Expected valid JSON`, no echo); bindings `id=bool`, `slug=bool`, `type:name=bool` (`Expected id=value`, `Expected slug=value`, `Expected type:name=enabled`); string maps `key=value` repeatable, refusing `__proto__|constructor|prototype` (`Unsafe key: <key>`) and duplicates (`Duplicate key: <key>`).
- The final body is parsed by the SDK request schema (`schema.parse`), whose zod issues are joined as `<path>: <message>` (`si.ts:157-167`). Zod messages **quote received enum and literal values** (captured `received 'PRIVATE-TARGET'`, `received 'staging'`, `received 'widget'`); `.strict()` schemas name unknown keys (`<root>: Unrecognized key(s) in object: 'reset_usage'`). Exit 2, before any client or network.

### 2.9 Generic renderers (classes L/D/G/C/S)

- `responseItems` (`sh.ts:82-90`) takes the list from the response: an array; else `data` if an array; else `data.records`; else `records`; else `[]` (a shape it does not know prints the empty phrase).
- `renderGatewayList` (`sh.ts:120-140`): `json` → `JSON.stringify(items, null, 2)` of the **raw items** (after any redaction); `yaml` → `dump(items, {noRefs:true, lineWidth:-1}).trimEnd()`; both print `[]` when empty. Otherwise an empty list prints `  No <label> found\n` (stdout, dim when coloured) with labels `configs`, `guardrails`, `providers`, `service API keys`, `user API keys`, `audit logs`, `config versions`, `deployments`, `integrations`, `catalog providers`, `integration models`, `MCP integrations`, `plugins`, `Admin guardrails` (capital A), `MCP mappings`. Non-empty `pretty` and `table` are the same box table (no banner, no indent); `markdown`/`csv` use `formatOutput`.
- Column choice (`displayColumns`, `sh.ts:96-118`): a key is eligible when no item holds an object/array there; first the preferred `id, slug, name, type, status, enabled, created_at, last_updated_at` that are eligible and present, then every other eligible key in JS sort order, **at most 8**. Labels: `_` → space, then each `\b\w` uppercased (`created_at` → `Created At`, `ai_provider_id` → `Ai Provider Id`, `is_default` → `Is Default`). Cell text: `null`/absent → empty, objects → `JSON.stringify`, else `String`.
- `renderGatewayDetail` (`sh.ts:142-165`): `json` → `JSON.stringify(record, null, 2)`; `yaml` → `dump(…).trimEnd()`; otherwise a two-column `Field`/`Value` table of the top-level entries, nested values as compact JSON. A non-object value is wrapped as `{ value }`. **An empty object prints nothing at all** (exit 0; captured `mcp integrations workspaces set`, whose response schema is `{}` strict).

### 2.13 Telemetry windows

`serializeWindow` (`SDK:17975-17994`): `end = --end ?? now`, `start = --start ?? end − days·86 400 000 ms`; `start > end` → `AISEC_USER_REQUEST_PAYLOAD_ERROR:Invalid telemetry query options or time window` (exit 1, no request). Timestamps are written by `toOffsetIso` in the **process's local time zone** with a numeric offset and **seconds truncated** (`2026-10-12T03:04:31+00:00` under `TZ=UTC`; the same instant under `TZ=Asia/Kolkata` is sent as `2026-10-01T05:30:00+05:30`, captured), years outside 0–9999 refused. `organisationId` is the tenant's `mgmtTsgId` (must be digits). The CLI parses `--start`/`--end` with `new Date(String(v))` (`si.ts:68-72`), so date-only strings are UTC midnight, date-times without an offset are local time, and many non-ISO strings are accepted; `--start` makes `--days` ignored (even an invalid one: `--days abc --start …` succeeded, captured). `--workspace` of every telemetry command except `cost` is sent unresolved and must match `^[A-Za-z0-9][A-Za-z0-9_-]*$` (a name with a space → the window error, exit 1, captured; a display name without spaces is sent as a slug, captured `workspaceSlug=Production`).

One attempt (`numRetries: 0`), redirects are errors, `--timeout` is the per-request deadline (a hang with `--timeout 700` → `✗ Error: AISEC_CLIENT_SIDE_ERROR:Request timed out`, exit 1).

### 8.4 Output (captured)

- Non-streaming: pretty chat/responses → the text (`choices[].message.content` joined; responses: `output[].content[]` parts of type `output_text` joined) + `\n` (`'Hello from stub\n'`, `'Hi there\n'`); an answer without text prints `\n`; pretty embeddings → `JSON.stringify(result, null, 2)`; json → `JSON.stringify(result, null, 2)`; yaml → `dump(result, {noRefs:true}).trimEnd()` (**default 80-column folding**, unlike the other gateway YAML). A response `status` of `failed`/`incomplete` is printed and then `✗ Error: Gateway generation ended with incomplete` (exit 1).
- Streaming: pretty writes each event's text as it arrives (chat `choices[].delta.content`, responses `response.output_text.delta`) and a final `\n` (`'Hello\n'`); json writes one compact JSON event per line (JSONL; `[DONE]` not echoed). A `response.failed`/`response.incomplete` event ends with the text so far **without** the newline and `✗ Error: Gateway generation ended with response.failed` (exit 1). Model text is written raw (control characters included).

### 8.5 Secrets

The key is only sent as `x-portkey-api-key` and never printed; the SDK debug log hashes it and omits bodies. Prompts and model output are never logged by the CLI.

### 8.6 Interruption

`SIGINT`/`SIGTERM` (`process.once`) abort the request: `\n  ✗ Error: Inference interrupted\n\n`, **exit 1** (both signals, captured), not 130/143; partial streamed text stays on stdout.

## Acceptance criteria

Each is a loopback executable test of airs-cli-rs; parity tests compare both CLIs where the behaviour is shared.

1. Every `gateway` management command uses only the selected tenant's `mgmt*` credentials and `mgmtTokenEndpoint`, `gatewayDataEndpoint`, `gatewayAdminEndpoint` and `iamEndpoint` (SDK default bases), sends `x-tsg-id` = the tenant TSG, and ignores every `PANW_*` variable; `gateway inference` uses only `gatewayInferenceEndpoint`/`gatewayInferenceApiKey`/`gateway*Model` (or `--endpoint`/`--model`), never the environment and never OAuth; tenant files are unchanged.

3. Pretty layouts of the W/WW/WD commands match §3–§5 byte for byte (banner, sections, key padding, colours of §2.3, `unknown`, `default`, `scope:`, `unbound`, `(none)`, cost dollars with JS `toFixed` rounding) except where a DESIGN §12 row changes them; the banner is printed only for pretty output and never before argument checks fail.
4. The generic list and detail renderers match §2.9 (column choice, labels, at most 8 columns, `Field`/`Value`, empty phrases with their labels, `[]` for empty json); `--output pretty|table|json` is honoured on every read, `markdown`, `csv`, `yaml` and unknown values are usage errors before the tenant (D51 precedent); `get`s print their record in the requested format (never YAML for table).
5. Every argument check of §2.4/§2.5 (flag syntax, UUIDs, numeric TSGs, scope names, workspace refs, windows, chart filters, paging, dimensions, columns, structured input, file inputs, output destinations) runs before the tenant is read and exits 2, and no message echoes a value, file content or credential.
6. Every write is sent once (one replay after a 401, none after a 403); a 5xx, transport failure or deadline after dispatch prints an outcome-unknown line naming the change (`the workspace may have been created`, `the API key may have been created; its one-time secret was not received`, …) and exits 1.
7. `workspaces create` reports partial provisioning from the SDK's structured recovery (scope created/deleted/retained, workspace created/unknown, bind pending) with an airs-cli-rs remedy command, never an SDK method name.
8. Workspace resolution never swallows a failed list and never passes an unmatched ref through; `scopes bind` refuses an unknown workspace; `scopes create` validates the name.
9. 11. Confirmations follow D81 and the DESIGN §12 decision on which writes confirm (open question 10); non-TTY without `--force` is a usage error before the tenant; declining or Ctrl-C changes nothing and removes a reserved secret file.
12. Acknowledgements, warnings and grant hints go to stderr; stdout carries only data (valid JSON with `--output json`); `--quiet` never removes identifiers from pretty data lines.
13. Server text (names, descriptions, messages, model output in pretty mode) goes through `terminal_safe`; error text is built from SDK error metadata only (DESIGN §6), never raw bodies; the grant hint is chosen from the failing plane, not message substrings.
14. `--debug` records method, path, status and headers only; `report` refuses `--debug`.
15. SIGINT/SIGTERM during any request (inference included) exits 130/143 with the DESIGN §13.2 `Interrupted; …` line saying whether a change may have been applied.

## Open questions / likely §12 divergences

Numbers are assigned by the orchestrator. Each is a safety or correctness fix unless marked "choice".

1. **Write replay (safety).** TS re-sends every gateway write up to 5 times on 5xx/timeouts (§2.6: 3 config POSTs, **3 API-key POSTs minting keys**, 6 workspace DELETEs, scope POSTs inside provisioning). Rust: D95, outcome-unknown lines.
2. **Never-live surface (safety).** §10 classification; the live tier exercises only reads (minus the secret-bearing ones) and, optionally, config create/update/delete in a designated workspace and one inference call. Recommendation: no gateway write at all in 0.10 live runs.
3. **One-time secrets (safety).** Keep `--secret-output`/`--show-secret` and the before-tenant destination check (parity); Rust also removes the reserved file on interruption, refuses a symlinked or existing path without following it, never replays the mint, and on an ambiguous failure says the credential may exist and was not received. Choice: whether `--show-secret` is allowed when stdout is a TTY only (recommendation: allowed always, as TS).
4. **Redaction (safety).** TS redacts per command and inconsistently (§11). Rust: one policy = SDK `redact_ai_gateway_secrets` for the operation **plus** the key-name rule, applied to lists and details of providers, api keys, integrations, MCP integrations, organisations and audit logs; string fields that hold JSON (`request_body`, `request_headers`) are withheld unless `--reveal-sensitive`; choice: keep TS over-redaction of `filter-boundaries`/`organisations info` (recommendation: redact only secret leaves, so the read is useful).
5. **stdout pollution (correctness).** `✓` acknowledgements and `⚠` warnings/grant hints on stdout break `--output json` (§2.3). Rust: stderr (D94/D106 precedent).
6. **Output formats (correctness).** `workspaces get`/`scopes get` print YAML for table/markdown/csv; empty `workspaces list --output json` prints prose; `{}` responses print nothing; YAML has an extra blank line; telemetry pretty is one JSON cell. Rust: `pretty|table|json` only (D51), correct table and json for every command; choice: a real pretty layout for telemetry (recommendation: keep the TS `Field`/`Value` table in 0.10 and print `data`'s scalar fields as rows).
7. **Validation order (correctness).** SDK checks (UUIDs, TSGs, scope names, refs, windows) fail after the tenant with exit 1; several window/paging checks run after the tenant; the banner precedes validation. Rust: all of them are usage errors before the tenant (AGENTS exit-code invariant); banner only on success paths.
8. **Workspace resolution (safety).** Failed lists are swallowed, unmatched refs pass through, `get` resolves on the admin plane but reads on the data plane, `scopes bind` binds non-existent slugs. Rust: a failed list is an error; unmatched → `workspace '<ref>' not found on the <plane> plane` (usage-like, exit 1); `bind` requires a resolved workspace; `get` by name reads on the plane where it was found (choice) or refuses (recommendation: read where found and say so on stderr).
9. **IAM scope safety (safety).** `scopes create` sends invalid names; `scopes delete` has no bound-workspace check; `bind` is GET-then-PUT (lost update). Rust: validate names; choice: `scopes delete` refuses a scope with resources unless `--force` names it twice (recommendation: refuse while bound, D81 prompt otherwise).
10. **Confirmations (safety, choice).** TS confirms deletes, replacements and rotations but not `organisations auth-settings update` (SCIM/SSO), `organisations self update`, `deployments update --rotate-auth`, `scopes bind`, credential-replacing `integrations update --key*`. Recommendation: D81 prompts for auth-settings update and deployment auth rotation; the rest unchanged. Prompts go to stderr and TTY detection uses stdin+stderr (TS uses stdout).
11. **Grant hint (correctness).** The AB03 test reads the message, which never carries `errorCode` (§2.7). Rust: choose the hint by the failing plane (data → workspace-scope grant, admin → tenant-root grant, IAM → IAM permission), on stderr.
12. **Inference credentials (safety).** TS reads `PANW_AI_GW_INFERENCE_API_KEY`/`_ENDPOINT` from the environment when the tenant lacks them. Rust: tenant (or `--endpoint`) only; missing → a fixed message naming the `gateway*` keys and `airs-cli-rs tenant set`.
13. **Inference interruption and output (correctness).** TS exits 1 with `Inference interrupted`; Rust 130/143 with the DESIGN §13.2 line. Pretty model text through `terminal_safe` (choice: only when stdout is a TTY; recommendation: always for pretty, never for json). YAML output is dropped (D51), so `--stream --output yaml` disappears.
14. **Telemetry windows (correctness).** Local-time offsets (TZ-dependent), `new Date` parsing, ignored `--days` with `--start`, unresolved `--workspace` names, the CLI's `--status-code 0` refusal. Rust: RFC 3339 inputs with offset required (as `report`), windows sent in UTC (`+00:00`, seconds precision — choice: keep the `+HH:MM` form for server compatibility), `--days` with `--start` a usage error, `--workspace` resolved to a slug for every telemetry command (as `cost`) or refused when it is not a slug (recommendation: resolve, once per invocation).
15. **Error and parser echoes (safety).** ZodError JSON with `received` values, YAML snippets of `--file`, key names in map errors, file paths. Rust: fixed messages naming the flag and field only (DESIGN §6); `--file` read with the D103-style rules (regular file, size cap, UTF-8) before the tenant.
16. **Fabricated results (correctness).** Deletes print `{success: true}` the server never sent; `workspaces create` silently falls back to the partial create response. Rust: acknowledgement lines on stderr (`Deleted config <id>.`), json prints nothing or `{"id":…,"deleted":true}` (choice; recommendation: an explicit result object, documented as CLI-made); a failed re-read is a warning, not silence.
17. **Dead and misleading flags (correctness).** `providers create --reset-usage` always fails; `organisations … --tsg-id` duplicates the tenant TSG and is not checked; `mcp integrations workspaces list` prints the whole integration. Rust: drop `--reset-usage` from create; default `--tsg-id` to the tenant and refuse a different one (safety: cross-organisation writes); use `get_workspaces` (choice: parity of the printed object vs the right endpoint; recommendation: the endpoint).
18. **Inline credentials (safety, choice).** `--key`, `--scim-token`, `--credential key=value` live in argv; only `--key` warns. Recommendation: keep `--key` with the stderr warning, add `--scim-token-stdin|--scim-token-file` and `--credential-file`, warn on every inline secret flag.
19. **`workspaces create --metadata` (choice).** Replaces `defaults.metadata` rather than merging; keep (documented) or merge (recommendation: keep, parity, mention in help).
20. **Report (choice).** `numRetries: 0` meets G7 in Rust (no 401 replay); keep the 25-source sequence and checks; the HTML/Markdown renderer is the shared environment-report renderer.
21. **Doctor.** Add the `Gateway API` check with the TS semantics of this spec's §12 (403 → warn), named per the rename.
22. **Help texts (choice).** Examples and descriptions renamed to `airs-cli-rs gateway …`; the doubled `report --days` default and the help of dropped formats change; TS help bytes are not a contract.
