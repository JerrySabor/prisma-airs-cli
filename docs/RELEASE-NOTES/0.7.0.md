M6b DLP: airs-cli-rs now covers every `runtime dlp` command of the TypeScript CLI except
`generate`. That includes filtering profiles, data patterns, data profiles, dictionaries
(with the keyword upload), and DLP backup and restore. It also moves to scm-sdk 0.1.1, so
red team target documents show only the fields the server sent.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.7.0
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## New commands

All under `runtime dlp`:
- `filtering-profiles list`, `get`, `replace`
- `patterns list`, `get`, `create`, `replace`, `patch`, `delete`
- `profiles list`, `get`, `create`, `replace`, `patch`
  - `profiles delete` explains that the DLP API cannot delete a profile, and sends nothing.
- `dictionaries list`, `get`, `create`, `replace`, `patch`, `delete`
  - `create` and `replace` upload the keyword file.
- `backup` and `restore <file>`

`runtime dlp generate` is dropped, like `redteam judge`.

## Safety

- **Every write is sent once.** A 401 is retried once with a fresh token; a 403 is never
  replayed. When the outcome is unknown, the CLI says so. A create also gets a hint to check
  the list before creating it again.
- **Predefined resources are protected.** Before every replace, patch or delete, the record is
  read. The command refuses records that are predefined, managed by a parent tenant, of an
  unfamiliar `type`, or that come back with a different id. Bodies with `type: predefined`
  are refused.
- **Confirmations.** Both deletes, every replace and restore ask on a terminal. A replace names
  the current fields it would drop. Without a terminal, `--force` is required.
- **Detection content stays out of errors and logs.** Regexes, keywords, bodies and `--set`
  values are never echoed in an error, and `--debug` never logs a request body.
- **Inputs are bounded.** Body, metadata and keyword files and `--body -` stdin are read as
  regular, size-capped files before the tenant is contacted.
- **Default lists are complete.** The custom-only lists read every page before slicing, so
  totals are honest. A walk that sees a repeated id or an empty middle page fails instead of
  printing a partial list.
- **Backups.** One airs-cli-rs file per run, written exclusively at 0600, and the path is
  checked before the tenant is read. Keywords are read per dictionary, and a failed read is a
  failed row (`complete: false`). TypeScript backups are refused.
- **Restore** offers `--dry-run`. A backup from another TSG needs `--allow-other-tenant`, and
  `--expect-tsg` is kept. Each create is one attempt, and the run stops at the first failure
  with `outcomeUnknown` named. `--on-conflict reconcile` uses a fixed suffix, so a re-run never
  creates another copy.

## scm-sdk 0.1.1

- The SDK is pinned to `=0.1.1`.
- `redteam targets get`, `list`, `create`, `update`, `probe`, `update-profile` and
  `targets backup` show and store only the fields the server sent. The SDK no longer
  fills in `ws_response_timeout: 110` or `basic_auth_location: "HEADER"` (D153).
- `targets backup` reads each target with the typed `get` (shown in `--debug` logs as
  `red_team.targets.get`). The file's contents are unchanged.

## Verified

The full loopback and parity suite passes (2234 tests). Against a real tenant:
- The DLP reads agreed with the TypeScript CLI on all 13 checks, including a backup from each
  CLI.
- The red team reads still agree on all 19 checks with scm-sdk 0.1.1.
- The write flow created, patched, replaced and deleted one pattern and one dictionary per CLI,
  and restored prefixed copies of the Rust pair: 30 checks, 6 resources created, 6 deleted,
  nothing left behind.

Data profiles are not written live: the DLP API cannot delete one, so their writes are tested
on loopback only.
