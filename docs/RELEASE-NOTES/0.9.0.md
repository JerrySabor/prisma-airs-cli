M6d Runtime extras: airs-cli-rs now covers the rest of the TypeScript CLI's `runtime` commands:
API keys, customer apps and their consumption, deployment profiles, scan logs, the dashboard and
sessions views, the HTML environment report, and backing up and restoring security profiles.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.9.0
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## Safety

- **API keys never reach the terminal.** `create` and `regenerate` write the new key to a new
  0600 `--key-file`, which is never overwritten. stdout shows only its last 8 characters and the
  file path; the key is never on stderr, in the debug log or in an error. Reads withhold any
  `api_key` member the server includes.
  TypeScript prints the key on stdout, even with `--quiet`.
- **Every write is sent once.** TypeScript re-sends a create up to 5 times, and a resent
  `regenerate` can rotate a key twice. When the outcome is unknown, the CLI says so.
- **Confirmations.** `api-keys regenerate` and `delete`, `customer-apps update` and `delete`, and
  `profiles restore` ask on a terminal. Without a terminal, `--force` is required.
- **No invented values.** Consumption counts the server didn't send show as `?` (or `null` in
  json), never `0`.
- **Restore never duplicates.**
  - A profile or topic list answered `{}` is treated as unknown, not empty.
  - A re-run reuses what an earlier run created.
  - The run stops at the first unknown outcome.
  - Cross-tenant restores need `--allow-other-tenant`.
  - TypeScript backup files are refused.
- **Files.** Reports, backups, key files and `sessions scan-content` output are new 0600 files,
  checked before the tenant is read. A destination that names no file (`out.json/`, `dir/..`) is
  refused before any request.
- **Paths and listings.** API key names and ids are checked as path segments, so `regenerate ..`
  can't reach another route. `--all` walks fail on a repeated row instead of printing a partial
  list.

## scm-sdk

Still pinned to `=0.1.1`. scm-sdk 0.2.0 is not adopted yet (DESIGN §15, G25). It accepts unlisted
enum values in responses, but enforces the vendor's UUID and RFC 3339 string formats and required
fields where the TypeScript SDK accepts any string, so one unexpected value would fail a whole
red team read.

## Verified

- The full loopback and parity suite passes (2,768 tests).
- Against a real tenant (2026-10-19), every live tier agrees with the TypeScript CLI:
  - the base comparison: 20 checks, with all 8 scans;
  - the red team reads: 19;
  - the DLP reads: 13;
  - the new runtime reads: 21;
  - the profile transfer flow: 15. It created 5 run-prefixed resources, restored them, verified
    them and deleted all 5.

**Not run live:**
- The API-key writes and the customer-app writes: the run can't create its own customer app or
  key without touching existing ones.
- `customer-apps get`: the tenant's service account gets HTTP 403 on both CLIs, so the live tier
  records it as unavailable.
- Model security: the tenant still has no access.
