M6f Supplychain: airs-cli-rs now covers the TypeScript CLI's AgentGuard commands, under the new name
`supplychain`. With it, every TypeScript command group is ported or deliberately dropped. The next
release, 1.0, renames the executable to `airs`.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.11.0
```

There are no store changes since 0.3. The `supplychain*` tenant keys (TypeScript `agentGuard*`)
have been read since 0.3.

## New commands

All under `supplychain` (TypeScript `agentguard`; there is no `agentguard` alias, D308):

- `scans list|ls`: the scan inventory, one page or `--all`
- `scans vulnerabilities <scanUuid> [--include-content]`: one scan's findings
- `stats`: the 30-day statistics
- `rules list|ls`: the rule catalog
- `report`: the HTML supply chain environment report, titled `Supply chain environment report`
  and written to `airs-supplychain-report-…` (D309, D310)

## Scans the service sends with nulls (G71)

On a real tenant, the service sends scan rows with `"fingerprint": null`. The shared API contract
(scm-sdk 0.2.2 and the TypeScript SDK) requires a string there, so both SDKs refuse the whole
answer. TypeScript prints its generic `AgentGuard request failed…` line for `scans list` and leaves
the report's Scans section unavailable.

airs-cli-rs reads scan pages through the SDK's raw read, with the same authentication, origin
policy, redirect refusal, size and validation bounds, retry rule and debug operation name as the
typed call. It decodes them with a tolerant projection:

- Every scan still needs a string `uuid`, and the page still needs its counts.
- Every other member may be `null`.
- Rows the SDK accepts print exactly as before (D324).
- A page the projection still refuses prints `The AgentGuard answer does not match the API
  contract`, with no upstream body (D325).

The fix belongs in scm-sdk and has been reported to its maintainer. The workaround goes away once
the SDK accepts these rows.

## Safety

- **Argument checks come first.** Every argument check is a usage error (exit 2), checked before
  the tenant is read, and names its flag (D314). `--max` and `--limit` accept decimal digits only
  (D315).
- **Incomplete finding lists fail.** When `scans vulnerabilities` returns fewer findings than
  `pagination.total_items`, the rows print, then a named line, and the command exits 1. An
  automated gate never passes on a truncated list (D319, G61).
- **Scanned content.** `--include-content` prints scanned artifact content on stdout only, with a
  sensitivity notice on stderr (D321). Content never reaches the debug log.
- **The report** reads aggregates only, through the same report renderer as red team and gateway.
  It is written to a new 0600 file, and its parent directory is checked before the tenant.
  Timestamps must carry a zone, so the report doesn't depend on the host's time zone; date-only
  values are read as UTC (D322).
- **Answers are bounded at 32 MiB**, with their own failure line (D320). Redirects are never
  followed.
- **Interruption** says what was and wasn't written (D323).

## Verified

- The full loopback and parity suite passes (3,480 tests).
- Against a real tenant (2026-10-20), every live tier agrees with the TypeScript CLI:
  - the base comparison: 20 checks, with all 8 scans;
  - the red team reads: 19;
  - the DLP reads: 13;
  - the runtime reads: 21;
  - the gateway reads: 40;
  - the new supplychain reads: 10. `stats`, `rules list`, `scans vulnerabilities` and the
    report's Statistics and Rules agree with TypeScript. `scans list` and the report's Scans
    section pass as G71: airs-cli-rs reads the rows, and TypeScript refuses the same answer twice.
    `--include-content` runs on airs-cli-rs only, and the check confirms the content stays out of
    the debug log and the live summary;
  - the profile transfer flow: 15. It created 5 run-prefixed resources and deleted all 5.

**Not run live:** model security, because the tenant still has no access.
