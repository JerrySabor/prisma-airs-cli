M3.5 foundations: the TypeScript CLI's `pretty` and `table` output for every command,
colour, a redacted `--debug` API log, Linux builds, and signed, notarised macOS binaries.

## Changes

- **Output formats.** Every command prints `pretty` (the default), `table` or `json`,
  matching the TypeScript layouts byte for byte apart from the rows below. Management
  reads use the tenant's `defaultOutput` when `--output` is absent. `markdown`, `csv`
  and `yaml` are gone: asking for one is a usage error (exit 2), and a `defaultOutput`
  naming one makes the tenant config invalid.
- **Colour.** The TypeScript CLI's colours, decided separately for stdout and stderr.
  `NO_COLOR` turns colour off, `CLICOLOR_FORCE` forces it on, `CLICOLOR=0` turns it
  off. Tables, JSON and bare values are never coloured.
- **`--debug`.** Writes one JSONL record per HTTP attempt (token requests, retries and
  replays included) to `$XDG_STATE_HOME/airs-cli/debug/` (default
  `~/.local/state/airs-cli/debug/`); the newest 20 logs are kept. Records hold the
  method, the URL without its query, the status and allow-listed header values only.
  Bodies, prompts, queries and credentials are never written.
- **Doctor** makes one attempt per probe (D49), so a throttled endpoint is reported at
  once instead of retried into the time budget.
- **Builds.** Static Linux musl binaries for x86_64 and arm64; Forgejo CI runs fmt,
  clippy, an MSRV check and the parity suite against the pinned TypeScript reference.

| D59 | `tenant path` rejects an invalid `--output` |

| D61 | The debug log lives in the XDG state directory (0700/0600, newest 20 kept) |
| D62 | Every attempt is logged, whatever the host |

| D64 | Debug records hold status and headers only, URLs without the query |
| D65 | Debug headers go through an allow-list; everything else is `***` |

D3 (`--debug` not ported) and D4 (JSON-only management output) are retired. D5 (scan
output) now covers `json` and `table`.
