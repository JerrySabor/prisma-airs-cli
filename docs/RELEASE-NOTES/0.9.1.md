airs-cli-rs 0.9.1 moves to scm-sdk 0.2.2. That closes G25, the reason 0.8 and 0.9 stayed on 0.1.1.
Answers are no longer refused over a string format, and every red team value that the API contract
refuses is now a usage error before the tenant, never an SDK error.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.9.1
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## scm-sdk 0.2.2

- The pin is `=0.2.2`, with the same features. Only the `scm-sdk` entry in `Cargo.lock` changes.
- **G25 closed.**
  - No response is checked against string formats any more (UUID, date-time, e-mail, URL), in any
    command (D306). An answer whose id, date or link the TypeScript CLI would refuse is read and
    printed unchanged.
  - Red team answers are checked against the same response schemas the TypeScript SDK uses.
  - Unlisted enum values and extra fields are kept, as before.
- The `PAN-AIRS` user agent now reports `0.2.2-rust-sdk`.

## Red team values checked before the tenant

The SDK refuses these before sending, with no field name in its error (G60). The CLI checks each one
first, exits 2, sends nothing and never echoes the value.

| Row | Command | Rule |
|---|---|---|
| D300 | `targets error-logs` | `--offset` and `--search` are refused whenever given; the API accepts only `--limit` |
| D301 | `list`, `targets error-logs`, `report --attacks` | `--limit` is at most 100 |
| D302 | `list` | `--status` and `--type` must use the API's values; `--target` must be a target UUID |
| D303 | `report --attacks` | `--severity` is one of `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` |
| D304 | `scan` | `--depth` and `--breadth` are at most 20 |
| D305 | `scan` | `--name` needs at least 3 characters (code points), as well as the existing length rules |

Other behaviour changes:

| Row | Change |
|---|---|
| D306 | No response is refused over a string format, in any command |
| D307 | `adapter update` without `--channel` stops before the update if the stored channel id isn't a UUID. The message names the field and says to pass `--channel` |

Red team ids the user supplies were already checked before the tenant (D141). Nothing the CLI sent by
default is dropped, so output is unchanged for every accepted command.

## Verified

- Against a real tenant (2026-10-19), every live tier agrees with the TypeScript CLI on scm-sdk 0.2.2:
  - the base comparison: 20 checks, with all 8 scans;
  - the red team reads: 19;
  - the DLP reads: 13;
  - the runtime reads: 21;
  - the profile transfer flow: 15. It created 5 run-prefixed resources and deleted all 5.

Model security was not compared live, because the tenant still has no access.
