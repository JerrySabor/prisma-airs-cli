M5 bulk scanning: airs-cli-rs now scans a file of prompts through the async AIRS API,
saves each job durably, and resumes a stopped job without submitting a prompt twice.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.5.0
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## New commands

- **`runtime bulk-scan --profile <name> --file <.csv|.txt>`**: submits the prompts in
  sequential batches (`--batch-size`, default 25), polls each batch's results and writes
  them to a CSV (`--output-file`, default `<profile>-bulk-scan.csv` in the current
  directory) in the TypeScript layout. `--session-id` groups the scans in the AIRS
  dashboard. Failed rows print a summary and exit 1.
- **`runtime resume-poll <stateFile>`**: continues a stopped job. It polls the receipts
  already accepted, submits only prompts that were never sent, and rewrites the CSV
  (`--output-file <new path>` re-points it).

## Safety

- **Exactly once.** The job state is saved (fsynced) before every submission and after
  every response. A submission whose outcome is unknown (a timeout, a 5xx, a dropped
  connection) is recorded as ambiguous and never resubmitted; `resume-poll` refuses to
  guess and names the prompts.
- **Private, durable state** in `$XDG_STATE_HOME/airs-cli/bulk-scans/` (default
  `~/.local/state/airs-cli/bulk-scans/`; 0700 directory, 0600 files, atomic writes).
  TypeScript state files are refused.
- **A `flock` job lock**, refused at once naming the holder; it can never go stale.
- **Files are never overwritten.** An existing output file is refused; the job's own CSV
  is rewritten atomically and only after its identity is checked; no parent directories
  are created; the default name always stays in the current directory.
- **Bounded waits.** `Retry-After` is capped at 60 s, polling is bounded, and Ctrl-C saves
  the job, names its state file and exits 130 (143 for SIGTERM).
- **No server text or secrets** are stored in the state or CSV.
- All input checks (profile, session ID, file encoding, size and quoting, at most 10,000
  prompts) run before the tenant is read.

## Verified

The full loopback and parity suite passes (1647 tests). Against a real tenant, the live
bulk flow interrupted a job after its first batch, `resume-poll` finished it with one
submission for the one pending batch, a second resume sent nothing and left the CSV
byte-identical, and the TypeScript CLI's verdicts agreed on every row.
