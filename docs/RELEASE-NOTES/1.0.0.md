airs-cli 1.0.0: the stable release. The command is now `airs`. The product, the crate
(`airs-cli` on crates.io) and the repository keep the name airs-cli. `airs-cli-rs` keeps
working through 1.x as a compatibility name. 1.0 also moves to scm-sdk 0.2.3, the red team
management API 0.86.0, and adds a Homebrew tap.

## Install or upgrade

```sh
brew tap cdot65/prisma-airs-cli
brew trust cdot65/prisma-airs-cli
brew install airs-cli               # or: cargo install --locked airs-cli
airs --version                      # 1.0.0
```

There is nothing to migrate. Tenants (`~/.config/airs-cli/`), debug logs, bulk-scan jobs,
backups and the fetched uv stay where they are, in the same formats. A 0.x bulk-scan job
resumes under 1.0, and 0.x backups restore. README "Upgrading to 1.0" has the details.

## The `airs` command (D326)

- `airs` is the program. `airs-cli-rs` is the same program under its 0.x name and prints the
  same output, through 1.x. The TypeScript `airs-cli` keeps its own name, since there is no
  `airs-cli` alias.
- Hints, remedies, usage lines and help examples now say `airs` where 0.x said `airs-cli-rs`
  (D73). Data, exit codes, streams and requests are unchanged.
- `cargo install` installs both names, as two copies of one program. The tarballs and the
  formula install `airs` with an `airs-cli-rs` link.
- **Another `airs` on `PATH`.** An unrelated program named `airs`, such as an npm package's
  bin, wins if it comes earlier on `PATH`. Check with `type -a airs` and `airs --version`;
  this CLI prints a bare version such as `1.0.0`.

## Homebrew

The public `cdot65/prisma-airs-cli` tap (github.com/cdot65/homebrew-prisma-airs-cli; first
released as the Forgejo `cdot/tap`) holds `Formula/airs-cli.rb`. It builds `airs` from the
published crates.io crate, so Rust is needed only while it builds.
The tap carries stable releases only. `scripts/homebrew-formula.sh` renders the formula from
the crate's crates.io checksum; docs/RELEASING.md §6 is the guide.

## scm-sdk 0.2.3 (red team management 0.86.0, DESIGN §15.24)

- **New target values are sent (D328).** `targets create|update|probe` and `targets restore`
  send `VERTEX_AI` and `N8N` connections, the `REALTIME` response mode, the `client_session`
  multi-turn config and a Vertex AI connection config. TypeScript refuses them. A Vertex AI
  `project_id`, `location` or `engine_id` outside its vendor pattern is refused before
  anything is sent.
- **New target answers are read and backed up (D329).** Targets with a Vertex AI or
  `client_session` config are read, printed redacted and backed up, where 0.11 and TypeScript
  refused the answer.
  - If the service masks a Vertex AI `project_id`, `location` or `engine_id`, that target
    can't be restored, so it is a failed backup row that names the masked fields.
  - A mask only in `customer_sa_email` is stored and marked `credentialsWithheld`.
  - Targets carrying `VERTEX_AI`, `N8N` or `REALTIME` without the new configs were read by
    0.11 but recorded as failed backup rows. They are now stored.
- **`audio_curl` is redacted (D327).** A target's `audio_curl` is `[REDACTED]` whole, like
  `curl`, and only its credentials join the secret set. 0.11 and TypeScript printed it raw.
- **Vertex AI identifiers.** `project_id`, `location` and `engine_id` print `[REDACTED]`
  because the service treats them as sensitive. They aren't registered as secrets (only a
  credential embedded in one is), so a target's endpoint, name or description that contains
  them still prints.
- **Key order (D35).** The four new fields (`audio_request_json`, `audio_curl`,
  `basic_username`, `basic_password`) print after the declared fields, no longer sorted
  among the unknown keys.
- Requests carry `PAN-AIRS/0.2.3-rust-sdk`. No other output changes.

G71 is unchanged: AgentGuard is byte-identical in 0.2.3, so `supplychain` still reads scan
pages through the tolerant projection until the SDK accepts `null` members.
