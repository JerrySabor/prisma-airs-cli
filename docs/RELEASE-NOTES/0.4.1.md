## Changes

- **`runtime topics revert` (D99).** Every profile update creates a new revision with a
  new `profile_id`, and older revisions keep referencing their topics, so the plain
  delete at the end of a revert is nearly always refused with HTTP 409. 0.4.0 reported
  that as a partial completion (exit 1). From 0.4.1 a 409 keeps the topic, prints a
  warning on stderr and exits 0, because the profile no longer references the topic:

  ```
    ⚠ Topic <name> is still referenced (by another profile or an older profile revision), so it was kept. Run `runtime profiles cleanup`, then `runtime topics delete <topic_id>`.
  ```

  The JSON record is `{"profileName": …, "deleted": [], "kept": [<topic_id>]}` and the
  pretty view says `Kept` instead of `Deleted`. Any other delete failure after the
  profile update is still a partial completion (exit 1).
- **CI.** The macOS job moved to `.forgejo/workflows/ci-macos.yml`, run only on demand,
  so push runs no longer wait for an offline runner.
