M4 runtime writes: airs-cli-rs now creates, updates and deletes topics and profiles,
applies and reverts topics on profiles, evaluates topics against a CSV, and cleans up
old profile revisions.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.4.0
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## New commands

- **`runtime topics create`**: creates a topic, or updates the highest revision of an
  existing name. **`update <topicId>`** (`--config` file), **`delete|rm <topicId>`**.
- **`runtime profiles create`** (policy flags or `--config`), **`update <nameOrId>`**
  (merges into the latest revision), **`delete|rm <nameOrId>`**.
- **`runtime topics apply` / `revert`**: add a topic to, or remove it from, a profile's
  topic guardrails. `revert` then deletes the topic with a plain delete.
- **`runtime topics eval`**: scans each prompt of a CSV against a profile and reports
  TP/TN/FP/FN, precision, recall, F1 and accuracy (`--rate`, `--concurrency`).
  **`runtime topics sample`** prints a CSV that eval accepts (`--output-file`, never
  overwrites).
- **`runtime profiles cleanup`**: deletes every revision of each profile except the
  latest. `--dry-run` previews; without `--force` it shows the list, asks, re-checks the
  listing and only then deletes.

## Safety

- **Every write is sent once.** No write is re-sent after a timeout or a 5xx, so a
  create cannot be duplicated; only a 401 is replayed once with a fresh token. When a
  failed write may have been applied, the error says `Outcome unknown: …`.
- **Every write uses the tenant's endpoints.** TypeScript's `topics create`, `apply`
  and `revert` ignore the tenant's `mgmtEndpoint` and fall back to `PANW_MGMT_*` or the
  production host (D93).
- **Read-modify-write on the highest revision**, with the profile read last, other
  topic references kept exactly as read, and nothing written when nothing changes.
- **Deletes ask first.** Confirmations need a terminal; scripts pass `--force`.
  `--updated-by <email>` selects the force endpoint; there is no git fallback.
- **Cleanup never guesses.** It reads the complete listing (no endless loop on
  `next_offset: 0`), skips a profile whose latest revision is tied or missing or whose
  revisions share an id, and stops at the first write with an unknown outcome.
- **Eval fails closed.** A scan that errors, times out or returns an unknown action
  stops the run with no metrics.
- All checks (topic limits, UUIDs, flags, input files) run before the tenant is read.

## Known service behaviour

On a real tenant every profile update creates a new revision with a new
`profile_id`, and older revisions keep referencing their topics. `topics revert`
therefore usually ends in partial completion: the profile is updated, the topic is
kept (HTTP 409) and the command exits 1 saying so. Run `profiles cleanup`, then
`topics delete`.
