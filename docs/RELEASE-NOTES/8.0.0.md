airs-cli 8.0.0: the Rust CLI replaces the TypeScript `@cdot65/prisma-airs-cli`. One version
now ships everywhere: the Forgejo release, crates.io (`airs-cli`), the Homebrew tap and npm
(`@cdot65/prisma-airs-cli`). The command is `airs`; `airs-cli` and `airs-cli-rs` are names
of the same program. 8.0 also ports the TypeScript CLI 7.3.0 (directional security
profiles) on scm-sdk 0.2.4.

## Install or upgrade

```sh
# Homebrew
brew tap cdot65/prisma-airs-cli
brew trust cdot65/prisma-airs-cli
brew install airs-cli                         # or: brew upgrade airs-cli

# npm (replaces a 7.x install in place)
npm install -g @cdot65/prisma-airs-cli@latest

# crates.io
cargo install --locked airs-cli

airs --version                                # 8.0.0
```

Use one channel: an install from another channel earlier on `PATH` shadows it, and `airs
doctor` warns (`Executable` check, D331).

## Upgrading from the TypeScript CLI (npm 7.x)

- `npm install -g @cdot65/prisma-airs-cli@latest` replaces the TypeScript CLI with a
  launcher for the prebuilt Rust binary (macOS arm64, Linux x64 and arm64). `airs-cli` keeps
  working and runs the Rust CLI (D330); `airs` is the same program. The package exports no
  JavaScript library.
- Run `airs tenant import --dry-run`, then `airs tenant import`, once: tenants move to
  `~/.config/airs-cli/`. The TypeScript registry is read, never changed.
- TypeScript bulk-scan checkpoints and backup files are not read. Finish the jobs and re-take
  the backups with `airs`.
- Scripts: docs/MIGRATION.md §2.2 lists every change (exit codes, fail-closed scans, renamed
  groups `aigateway` → `gateway` and `agentguard` → `supplychain`, dropped
  `markdown|csv|yaml` output, no `PANW_*` environment credentials), each pinned by a test.

Upgrading from airs-cli 1.0.0 (the Rust CLI's previous release) needs nothing: state,
backups and jobs stay where they are, in the same formats. There was no 1.0.1 or 1.1.0.

## Directional security profiles (TypeScript CLI 7.3.0, DESIGN §13.17)

- `runtime profiles create|update` and `runtime topics apply|revert` take `--direction`
  (`prompt`, `response`, `tool-call`, `tool-response`) and `--ai-profile-index`;
  `--[no-]enable-full-conversation-inspection`, `--no-mask-data-inline` and
  `--no-mask-data-in-storage` are new; `create --config` names the profile from the file,
  and `--config` is exclusive with every write flag. Profile views, the runtime report and
  profile backup and restore read every direction.
- A live run against a tenant (2026-10-22) accepted every direction for creates, edits,
  topic apply and revert, backup and restore. Directional profiles are **supported, for
  single-entry profiles**.
- **D335.** A flag create with `--direction` also writes the other three directions as `{}`:
  the service refuses a directional entry without all four, so TypeScript 7.3.0's
  one-direction body fails with HTTP 400.
- **D336.** A directional flag create whose flags fill no direction (none, or shared settings
  only) is refused before anything is sent (exit 2), since the service refuses a policy with
  no protection in any direction.

### Known limitations

- **Not verified live:** profiles with several AI entries (`--ai-profile-index`), DLP blocks
  inside a direction, and the runtime report's `Protection configurations` column. The
  offline tests cover them.
- **Service rules are not checked before sending,** except D336: every directional entry
  needs all four direction keys (a `--config` body must list them); `response` refuses
  `prompt-injection`; `toxic-content` takes only `block` or `allow` per level. A write that
  breaks one fails with HTTP 400 (exit 1), with no response body shown.
- **`dlp_tenant_id` on writes.** A flag `profiles update`, `topics apply|revert`, `profiles
  restore` and `profiles update --config` without the key do not send `dlp_tenant_id`. The
  service then answers `dlpTenantId: "none"`; the effect on a stored DLP tenant binding is
  unknown, and no `get` or `list` returns the field. This matches TypeScript 7.3.0 and
  affects legacy profiles too. A `--config` file that holds the key sends it.

## scm-sdk 0.2.4 (DESIGN §15.25)

- `scm-sdk = "=0.2.4"`, the TypeScript SDK 0.35.0 overlay. Every profile request body is
  checked with the 0.35.0 request schema before the tenant is read.
- Profile reads and writes are validated without the SDK's response defaults, so lists, gets,
  backups and restores keep exactly what the service sent (no output change). An unexpected
  value in a new profile field is printed and backed up as sent (D334).
- `Cargo.lock` moves `rustls-webpki` to 0.103.16 and `webpki-root-certs` to 1.0.10
  (RUSTSEC-2026-0382, -0383).

## The rest of 7.3.0

Highest-revision profile lookups in `topics apply|revert`; ref and group metadata kept;
`profiles create|update` print a status line and honour the tenant's `defaultOutput`;
`--active` only when given; `--dlp-profiles` and `--[no-]mask-data-inline` without
`--dlp-action` on update; `revert` refuses a topic the profile does not reference.

Behaviour that still differs from TypeScript 7.3.0 on purpose: a create with no policy flag
is refused (TS creates an empty policy, D102); `revert` keeps a still-referenced topic with
exit 0 (D99); some layout refusals exit 2 after the profile is read.
