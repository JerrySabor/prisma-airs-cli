M6c Model Security: airs-cli-rs now covers every `model-security` command of the TypeScript CLI:
security groups, rules, rule instances, scans and their evaluations, violations and files,
models, labels, `pypi-auth` and `install`.

## Install or upgrade

```sh
cargo install --locked airs-cli     # or download a tarball below
airs-cli-rs --version               # 0.8.0
```

No store changes since 0.3; tenants imported with `tenant import` keep working.

## Safety

- **Every write is sent once,** including the billed `scans create`. A 401 is retried once with a
  fresh token; a 403 is never replayed. TypeScript re-sends a write up to 5 times. When the outcome
  is unknown, the CLI says so.
- **Confirmations.** `groups delete`, `labels set` and `labels delete` ask on a terminal, and
  `labels set` names the labels it would drop. Without a terminal, `--force` is required.
- **Deletes are verified.** A group counts as deleted only on a 404 or a tombstone. TypeScript
  reports "deleted" whenever the re-read fails.
- **No invented values.** Counts the server didn't send are shown as `?` (or `null` in json),
  never `0`. A pending scan no longer reads "0 failed".
- **Credentials stay out of output.** `pypi-auth` withholds the credential in every format. The
  full URL is written only to a new 0600 `--url-file`. Model URIs have their userinfo, query and
  fragment withheld.
- **`install`:**
  - It never puts the credential in argv. uv gets it through its named-index environment
    variables, and the CLI checks afterwards that `pyproject.toml` and `uv.lock` hold none.
  - `uv add --no-build` keeps third-party build code from seeing it.
  - `--dir` must not exist, and must not sit inside a uv workspace.
  - On a signal, the CLI forwards it to uv and waits for uv to exit.
- **`--fetch-uv`** installs a pinned uv 0.12.17, checked against the release's SHA-256 values,
  under `$XDG_DATA_HOME/airs-cli/tools`.
- **Lists.** Every documented paging flag works, `--scan-origin` actually filters, and walks
  that see a repeated row or an empty middle page fail instead of printing a partial list.

## scm-sdk

Still pinned to `=0.1.1`, now with the `model-security` feature enabled. scm-sdk 0.2.0 is not
adopted yet (DESIGN §15, G25). It validates the red team responses against the vendor's 0.93.0
schemas. Those schemas accept unknown keys and new enum values, but they enforce UUID and RFC 3339
string formats, required fields and non-null types that the TypeScript SDK does not check. So a
record the service sends in another shape would fail a whole read in Rust where TypeScript prints it.

## Verified

- The full loopback and parity suite passes (2,466 tests).
- The pinned uv archives were downloaded and checked against the release's `sha256.sum`, and the
  CLI's reader extracted `uv` from each of the four.
- Against a real tenant, the base comparison (20 checks), the red team reads (19) and the DLP reads
  (13) still agree with the TypeScript CLI.

**Not run live:** the tenant's service account has no model-security access. Both CLIs get HTTP
403, and `pypi/authenticate` refuses too. So the model-security reads, writes and `pypi-auth` are
verified on loopback only. The billed scan flow was skipped, and `install` is never run live.
